# moyami 초기 공개 구현 기록

## 반영 범위

- 첫 방문에 계정 화면을 표시합니다. 최초 관리자는 배포자가 생성한 `BOOTSTRAP_KEY`로 가입하고, 이후에는 아이디·비밀번호로 로그인합니다.
- 최초 관리자 생성과 초대 키 소비는 Redis Lua 트랜잭션으로 처리합니다. 동시에 요청해도 관리자가 둘 생기거나 같은 키로 두 번 가입하지 않습니다.
- 초대 키는 관리자만 발급하며 24시간·1회 사용입니다. 발급 직후 취소할 수 있습니다.
- 비밀번호 scrypt 해시, 해시로 저장한 세션 토큰, HttpOnly 쿠키, 로그아웃 시 세션 폐기, 인증 시도 제한, JSON·Origin 검사를 적용했습니다.
- Vercel에서는 Upstash REST API를 이용하고, 로컬 단일 프로세스에서는 `data/auth.json`에 계정을 저장합니다. 파일은 임시 파일 작성 후 rename으로 교체합니다.
- 브라우저 localStorage와 IndexedDB는 계정 ID로 구분합니다. 다른 탭의 로그인·로그아웃도 반영합니다. 동기화 기능은 추가하지 않았습니다.
- 기본 확장 저장소와 기본 소스 선택을 제거했습니다. 빈 서재에서 저장소 주소를 추가하도록 안내합니다.
- 표시 이름·프로젝트 이름·주소는 배포자가 정합니다. 연결 확장 패키지도 해당 앱 주소에 맞춰 빌드합니다.
- 키 생성 도우미 → Vercel Deploy Button → Upstash 연결 → 첫 가입 순서로 안내합니다. 생성한 키 값은 배포 링크에 포함되지 않습니다.
- GitHub 공개본에는 기존 개인 배포 이력, 토큰, `.state`, 실험 기록을 옮기지 않았습니다. Moya UI와 의존성의 라이선스는 유지합니다.

## 검증

- 실제 Redis를 포함한 서버 테스트 41개 통과.
- 실제 서버와 모바일 Chromium으로 관리자 가입, 초대 가입, 로그아웃, 탭 간 로그아웃, 계정별 저장 격리, 빈 저장소, 배포 키 도우미 확인.
- 기존 리더·소스 UI 브라우저 회귀 47개. 기본 저장소 자동 삽입에 의존하던 테스트는 저장소를 명시적으로 등록하도록 변경했고, 설정창 닫힘의 포커스 복원이 끝난 뒤 키보드 단축키를 검사하도록 수정했습니다.
- Chromium 연결 확장 회귀와 PWA 설치·오프라인 셸·업데이트 회귀 통과.
- 새 폴더에서 npm ci 및 Vercel CLI build 통과. Node.js 22 함수 출력 약 5.9MB, 정적 출력 약 2.7MB. 빌드 검증에만 쓴 빈 Vercel 프로젝트는 삭제했습니다.
- GitHub Actions에서 Redis·빌드·가입·리더·PWA 테스트를 자동 실행합니다.

## 배포 검증의 경계

이번 작업은 공개 저장소, 키 생성 페이지, 배포 구성과 Vercel 빌드를 검증했습니다. 새 사용자의 GitHub/Vercel 가입, Upstash 약관 동의 및 플랜 선택까지 대행한 것은 아닙니다. 배포 버튼을 누른 계정 소유자가 해당 절차를 완료해야 합니다. 기존 서비스 운영 배포는 변경하지 않았습니다.

원본 사이트의 인증·IP 차단, iOS/Android 연결 확장 배포 서명 조건은 기존과 같습니다. 사용자별 읽기 상태를 서버에 동기화하거나 이메일로 비밀번호를 복구하는 기능은 이 범위에 포함되지 않습니다.
